# 404

## When it applies

Every site has one. WordPress and Sage ship an unstyled placeholder, and a
visitor who mistypes a URL will find it. The 404 is design, not design system:
phase 5 of `figma-design-system` builds it from the comp's 404 board, or derives
it when the file has none.

## Blade skeleton

The template extends the layout, so the header and footer render around it. The
page's only `<h1>` is the heading here:

```blade
@extends('layouts.app')

@section('content')
  <section class="container flex flex-1 flex-col items-center justify-center text-center">
    <p class="font-display ... leading-none" aria-hidden="true">404</p>
    <div class="flex w-full flex-col items-center gap-6">
      <h1 class="heading-3">{{ __('Page Not Found', '__TEXT_DOMAIN__') }}</h1>
      <p class="text-body xl:text-lead mt-0 max-w-[51rem]">{{ __('It looks like the page you’re looking for is no longer available or may have moved.', '__TEXT_DOMAIN__') }}</p>
      <a class="btn btn-primary w-full xl:w-auto" href="{!! esc_url(home_url('/')) !!}">{{ __('Return To Home', '__TEXT_DOMAIN__') }}</a>
    </div>
  </section>
@endsection
```

- A themed 404 needs a heading, a sentence, and a way back. Add a search form when the site has search.
- The button uses the button role from the design system (`btn-primary`), not a color name.
- With no 404 board in the file, derive the page from the display type, the button classes, and the container, mark it `derived` in the map, and add "no 404 design" to the questions for design.
- A block's entrance directives aren't wired here: the template renders plainly, with no hidden state to flash.

## Canvas skeleton

None. A 404 is a template, not a block, so it has no editor canvas.

## Built from

- `app.blade.php`, the layout the template extends.
- `button-primary.css`, for the button role.
- `typography.css`, for the heading and text-lead classes.

## Rules that matter most

- I18N-1: every visible string goes through `__()` with the text domain.
- ESC-1: the home URL prints as `{!! esc_url(home_url('/')) !!}`.
- VIEW-3: a template owns the page's `<h1>`, unlike a block, which uses an `<h2>`.
- VIEW-6: colors and sizes come from tokens and type classes.
- A11Y-5: the large "404" numerals are decorative and `aria-hidden`.
- ESC-2: plain text prints with `{{ }}`.

## Adapt per design

- The layout: the numerals' size, the alignment, and the space around the copy.
- The wording, kept short and kind.
- An illustration or a search field, if the comp shows one.
- The number of buttons: a way home is required, and a second link is optional.

## Do not change

- The page extending the layout, so the header and footer stay.
- The way back to the home page.
- The heading as the page's `<h1>`.
- The unstyled WordPress 404 never staying in place because the design didn't cover it.

## Tests to write

- Every visible string goes through `__()` with the kit's text domain.
- The button uses the primary role and links home through `esc_url`.
- The view extends `layouts.app`, so the header and footer render around it.
- Load a URL that doesn't exist in the browser: the themed page renders inside the layout at desktop and phone widths, and the way back works.
- A note on the harness: `render-harness.mjs` can't render `@extends` and `@section`, so the kit's own 404 test reads the view's text, tolerant of whitespace. Keep any test of that kind to what the harness can't reach.
